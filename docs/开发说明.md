# 开发说明

界面是 WebView 里的单页应用（`web/`），原生层（`android/`）负责加密存储、文件读写、指纹和本机 OCR。另有一个电脑端局域网 OCR 服务（`ocr/`），给 OCR 版的「电脑识别」用。

## 目录

```
web/                 页面（打包时作为 APK 的 assets）
  index.html         按顺序加载 js/ 下的脚本
  js/
    lib/             bill_parser.js（订单截图 → 订单，与 ocr/bill_parser.py 一致）、bill_file.js（支付宝 / 微信账单文件）
    util.js defaults.js store.js query.js router.js ui.js scrollbar.js vlist.js gesture.js
    pages/           home、board（自定义看板）、list、add（记一笔）、report、me、tags、accounts、
                     manage（预算 / 分类 / 账本）、help（使用说明，改功能时和 docs/使用说明.md 一起改）
    merge.js         合并分类 / 账户 / 账本 / 标签，可撤销
    security.js io.js stress.js main.js
    import/          ocr（截图识别）、bill（支付宝 / 微信账单）、kbf（随手记备份）
android/
  app/src/main/      MainActivity（WebView + JS 桥）、SecureStore（加密数据库）、KbfReader（随手记备份）
  app/src/lite/      正式版：空的 LocalOcr
  app/src/ocr/       OCR 版：LocalOcr、OcrEngine（ONNX Runtime 实现的 PP-OCR）、assets/models
  ocrtest/           OCR 测速、量化、对比测试
ocr/                 电脑端 OCR 服务（RapidOCR + OpenVINO + FastAPI）
docs/                使用说明、本文件、截图
```

`web/js/` 下是普通脚本（不是 ES 模块），共享全局作用域，页面里的 `onclick="..."` 直接调用全局函数，不需要打包工具。新增文件要加到 `index.html`；加载时就执行的顶层代码只能用排在前面的文件里定义的东西。

调试页面可以直接在电脑浏览器里打开 `web/index.html`（最好用 `python -m http.server` 起个服务）：数据存在 localStorage、不加密，原生功能不可用；「我的」里有「重新生成示例数据」和「压力测试」。

## 打包 APK

需要 JDK 17、Gradle 8.7、Android SDK（路径在 `android/build_apk.ps1`、`android/local.properties` 里）。

```bash
android\build_apk.bat
```

同时打正式版（lite）和 OCR 版（ocr），复制到 `dist/`，版本号是打包时间。页面直接取自 `web/`。
没有发布签名配置（`android/keystore.properties`）时自动用 debug 签名，可以正常编译和安装，但不能覆盖安装 Releases 里的正式包。

| | 包名 | 说明 |
|---|---|---|
| lite | `com.xunji.app` | 不带识别导入，也不申请网络权限 |
| ocr | `com.xunji.app.ocr` | 内置 OCR 模型；压力测试、示例数据只在这个版本显示（`BuildConfig.TEST_TOOLS`） |

`android\build_apk_emu.bat` 额外带 x86_64 库，给 MuMu 等模拟器用。

## 电脑 OCR 服务

```bash
python -m venv ocr\.venv-rapid
```

```bash
ocr\.venv-rapid\Scripts\python -m pip install -r ocr\requirements.txt
```

```bash
ocr\start.bat
```

窗口里会打印局域网地址，填到 App「识别账单导入 → 电脑识别」。配置在 `ocr/ocr_config.ini`（首次运行生成）：`token` 设了之后请求要带 `X-Token` 头；`save_uploads = 1` 会把截图和识别结果存到 `ocr/uploads/`。
打包成 exe：`ocr\packaging\build_exe.bat`，输出到 `dist/洵记OCR/`。

## OCR 模型

APK 只用 `assets/models/` 里的 `v5_det.onnx` + `v5f_rec.onnx` + `v5f_keys.txt`（约 11 MB）。`v5f` 是 PP-OCRv5 识别模型的加速版：常数乘加并入卷积、只量化卷积的 INT8、裁成常用 7111 字、直接输出字号（脚本在 `ocrtest/q_fold/`）。对比用的 v5 / v6 模型用 `ocrtest/prepare_models.py` 生成，放在同一目录也不会打进 APK。

## 数据格式与加密

- 数据库 `xunji.db`：随机 256 位数据密钥做 AES-256-GCM 加密。数据密钥由 Android Keystore 保护后存在本机；设了密码后再用 PBKDF2-HMAC-SHA256（12 万次）派生的密钥加密一份写进文件，换机时凭密码解开。
- 流水按年份切片、按列存，字符串走字典（20 万条约 13 MB）；只重写有变化的年份，由原生层后台线程加密写盘。所以改流水要换新对象，不要原地修改。
